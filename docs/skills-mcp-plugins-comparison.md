# Skills、MCP、Plugin 的区别与 1+1>2 的整合方案

## 概述

在 AI CLI 工具（如 Claude Code、OpenCode）的扩展生态中，有三个核心概念：**Skills**、**MCP (Model Context Protocol)** 和 **Plugins**。它们各自有不同的设计目标和能力，通过有机组合可以实现 1+1>2 的协同效应。

---

## 三者的定义与定位

### 1. Skills：提示词模板

**本质**：预定义的 AI 行为指令和知识注入

**作用机制**：

- 通过 `description`、`instructions` 等元数据引导 AI 的行为
- 在特定条件下自动激活（如关键词匹配）
- 注入知识库、工作流规范、代码风格

**数据流**：

```
┌─────────────────────────────────────────────┐
│  AI 模型                         │
│  └───> 读取 Skill 文本              │
└─────────────────────────────────────────────┘
```

**特点**：

- ✅ **静态**：内容固定，运行时不变
- ✅ **轻量**：只是文本，无代码逻辑
- ✅ **声明式**：通过元数据描述何时激活
- ❌ **无能力扩展**：不能调用工具、监听事件

**适用场景**：

- 代码规范（如："使用 2 空格缩进"）
- 项目特定工作流（如："先运行 tests，再 build"）
- 知识库注入（如：项目结构说明）

---

### 2. MCP：工具协议

**本质**：标准化工具接口

**作用机制**：

- 提供 JSON Schema 定义的工具
- AI 通过函数调用主动请求
- Server 执行实际逻辑并返回结果

**数据流**：

```
┌───────────────────────────────────────────────┐
│          AI 模型                             │
│          ↓ (function call)                    │
│  ┌──────────────────────────────┐        │
│  │   MCP Client (CLI)         │        │
│  │  ┌─┬─┐                  │        │
│  │  │ │ │                     │        │
│  │  ▼ ▼ │                  │        │
│  │ memory_search()         │◄───────┤
│  │ memory_record()         │        │
│  │ memory_update_long_term() │        │
│  └─┴─┘                  │        │
│  └──────────────────────────────┘        │
│          ▼ (JSON response)                 │
└───────────────────────────────────────────────┘
                ▼
        ┌─────────────────────────┐
        │  MCP Server        │
        │  ┌───────────────────┐ │
        │  │ Storage/Search │ │ │
        │  └───────────────────┘ │ │
        └─────────────────────────┘ │
        ┌─────────────────────────┐ │
        │  External Services  │ │
        │  (DB/API/Embedding)│ │
        └─────────────────────────┘ │
        ▼
    ┌─────────────────────────────────────┐
    │  数据持久化层              │
    └─────────────────────────────────────┘
```

**特点**：

- ✅ **双向通信**：AI ↔ Server ↔ 持久化系统
- ✅ **通用协议**：跨平台、跨工具支持
- ✅ **类型安全**：JSON Schema 确保参数正确
- ✅ **异步执行**：工具调用不阻塞 AI 响应
- ❌ **被动触发**：需要 AI 主动调用

**适用场景**：

- 数据查询（如：搜索历史对话、查询决策记录）
- 数据写入（如：保存对话、更新长期记忆）
- 外部服务集成（如：API 调用、数据库操作）

---

### 3. Plugins：功能包与事件系统

**本质**：可分发的扩展机制

**作用机制**：

- 打包功能（可包含 Skills、MCP、自定义代码）
- 监听和响应系统事件
- 提供自定义工具和 UI 扩展点

**数据流**（以 OpenCode Plugin 为例）：

```
┌──────────────────────────────────────────────────────────────────┐
│                    OpenCode Core                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ Plugin System                                      │  │
│  │  ┌──────────────────────────────────────────────┐  │
│  │  │ Plugin: universal-memory                  │  │
│  │  │  ┌──────────────────────────────────────┐│  │
│  │  │  │ Event: session.idle               ││  │
│  │  │  │ ┌─────────────────────────────────┐│  │
│  │  │  │  │  1. Fetch messages          ││  │
│  │  │  │  │ 2. Extract last exchange ││  │
│  │  │  │  │ 3. Build payload          ││  │
│  │  │  │  │ 4. Call universal-memory-││  │
│  │  │  │  │     record            ││  │
│  │  │  │  └───────────────────────────┘│  │
│  │  │  ┌──────────────────────────────┐  │
│  │  │  │  Custom Tool (via tool hook)│  │
│  │  │  └──────────────────────────────┘  │
│  │  └────────────────────────────────────────┘  │
│  └────────────────────────────────────────────────┘  │
│                                                   │
│  ┌───────────────────────────────────────────────┐ │
│  │ MCP System                                   │ │
│  │  ┌─────────────────────────────────────────┐ │
│  │  │ MCP: universal-memory               │ │
│  │  │  - memory_search                   │ │
│  │  │  - memory_record                  │ │
│  │  │  - memory_update_long_term        │ │
│  │  └─────────────────────────────────────────┘ │
│  └───────────────────────────────────────────────┘ │
│                                                   │
│  ┌───────────────────────────────────────────────┐ │
│  │ Skills System (可选)                         │ │
│  │  - memory-assistant.Skill.md            │ │
│  │     → 提示 AI 使用记忆工具          │ │
│  └───────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────┘
```

**特点**：

- ✅ **事件驱动**：响应 `session.idle`、`message.updated` 等事件
- ✅ **工具扩展**：通过 `tool` hook 添加自定义工具
- ✅ **功能打包**：可包含依赖、配置、文件
- ✅ **自动化工作流**：无需手动配置
- ✅ **可分发**：发布到 npm，一键安装

**适用场景**：

- 自动化任务（如：会话空闲时保存对话）
- 集成外部服务（如：监控、通知）
- 代码规范执行（如：自动格式化、lint）

## 三者能力对比矩阵

| 能力维度         | Skills              | MCP                   | Plugins                |
| ---------------- | ------------------- | --------------------- | ---------------------- |
| **提供工具 API** | ❌                  | ✅                    | ✅ (通过 MCP hook)     |
| **引导 AI 行为** | ✅                  | ⚠️ (通过 description) | ✅ (通过 Skills + MCP) |
| **事件监听**     | ❌                  | ❌                    | ✅                     |
| **自动化执行**   | ❌                  | ❌                    | ✅                     |
| **持久化存储**   | ❌ (需配合 MCP)     | ✅                    | ❌ (需配合 MCP)        |
| **打包分发**     | ⚠️ (需手动)         | ✅                    | ✅                     |
| **类型安全**     | ⚠️ (文本)           | ✅ (Schema)           | ⚠️ (取决于实现)        |
| **跨平台**       | ⚠️ (取决于工具支持) | ✅                    | ⚠️ (取决于平台)        |

## 1+1>2 的整合方案

### 方案 A：Skills + MCP

**描述**：Skill 描述何时调用 MCP 工具

**工作流**：

```
用户提问
  ↓
Skill 检测关键词（"之前"、"历史"、"决策"）
  ↓
Skill 调用 memory_search() MCP 工具
  ↓
MCP Server 搜索数据库
  ↓
返回相关记忆
  ↓
AI 结合记忆回答
```

**优势**：

- ✅ 自动触发：无需 AI 记住何时搜索
- ✅ 类型安全：MCP 工具有 Schema 定义
- ✅ 跨平台：任何支持 MCP 的工具都可用

**劣势**：

- ⚠️ 依赖 AI 自觉：Skill 只是建议，不保证调用
- ⚠️ 无自动化：需要 AI 主动触发

**适用场景**：

- Claude Code 的记忆系统（当前实现）
- 需要搜索历史但不自动化保存的场景

---

### 方案 B：Plugin + MCP

**描述**：Plugin 监听事件并调用 MCP 工具

**工作流**：

```
AI 对话进行中...
  ↓
用户离开会话
  ↓
session.idle 事件触发
  ↓
Plugin 获取最后一条对话
  ↓
Plugin 调用 memory_record() MCP 工具
  ↓
MCP Server 保存对话
  ↓
对话持久化
```

**优势**：

- ✅ 真正自动化：事件驱动，无需 AI 参与
- ✅ 可靠性：每次会话结束都执行
- ✅ 类型安全：MCP 工具保证数据格式正确

**劣势**：

- ⚠️ 平台依赖：只有 OpenCode 支持事件系统
- ⚠️ 需要 MCP：依赖 MCP Server 提供写入能力

**适用场景**：

- OpenCode 自动保存对话（universal-memory-mcp 实现）
- 任何需要自动化记录的场景

---

### 方案 C：Plugin + Skills

**描述**：Plugin 监听事件并使用 Skill 改变 AI 行为

**工作流**：

```
session.updated 事件触发
  ↓
Plugin 检测会话状态变化
  ↓
Plugin 动态加载或修改 Skill
  ↓
AI 在下一个请求中使用新行为
```

**优势**：

- ✅ 动态配置：运行时调整 AI 行为
- ✅ 上下文注入：根据项目或会话状态注入不同知识

**劣势**：

- ⚠️ 仅行为引导：不能调用实际工具
- ⚠️ 复杂度高：需要管理 Skill 生命周期

**适用场景**：

- 多项目协作（不同项目不同规范）
- 会话感知功能（如：测试环境 vs 生产环境不同策略）

---

### 方案 D：Plugin + MCP + Skills（三剑合璧）

**描述**：Plugin 通过事件监听自动化 MCP 工具调用，同时通过 Skill 引导 AI 使用

**架构**：

```
┌──────────────────────────────────────────────────────────────┐
│  Plugin: universal-memory (OpenCode)                     │
│  ┌────────────────────────────────────────────────────┐  │
│  │ Event Hook (session.idle)                 │  │
│  │  ┌─────────────────────────────────────────┐  │
│  │  │ 自动触发保存流程                 │  │
│  │  │ 1. 获取最后一条对话           │  │
│  │  │ 2. 调用 memory_record (MCP) │  │
│  │  │ 3. 验证保存成功               │  │
│  │  └───────────────────────────────────┘  │  │
│  │                                         │  │
│  │  Tool Hook (memory_search)        │  │
│  │  ┌────────────────────────────────────┐  │
│  │  │ 供 AI 搜索历史对话        │  │
│  │  └────────────────────────────────┘  │  │
│  └────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────┘
                ▼
        ┌─────────────────────────────────────┐
        │ MCP Server                      │
        │  - memory_search()                │
        │  - memory_record()               │
        │  - memory_update_long_term()     │
        └─────────────────────────────────────┘
                ▼
        ┌─────────────────────────────────────┐
        │ Storage                       │
        │  - daily/*.md                   │
        │  - long_term/MEMORY.md         │
        └─────────────────────────────────────┘
```

**工作流**：

```
【自动化保存】
session.idle 触发 → Plugin 调用 memory_record() MCP → 保存

【主动搜索】
用户询问"之前的讨论"
  ↓
memory_search() MCP Tool 暴露给 AI
  ↓
AI 发现 Tool 并调用
  ↓
返回历史记忆
```

**优势**：

- ✅ **完全自动化**：保存无需 AI 参与，搜索有 AI 参与
- ✅ **类型安全**：MCP Schema + Tool Hook 类型约束
- ✅ **易分发**：npm install 即可全部安装
- ✅ **可维护**：三个组件职责清晰

**劣势**：

- ⚠️ 复杂度最高：需要维护多个系统
- ⚠️ 调试困难：多层调用链

**适用场景**：

- 完整的记忆系统（universal-memory-mcp 最终目标）
- 需要可靠自动化的生产环境

---

### 方案 E：Plugin + MCP + Skills + 额外功能

**描述**：在方案 D 基础上添加更多功能

**额外功能示例**：

- **自动化整理**：定期清理重复记忆、分类归档
- **智能提醒**：检测长期未保存的会话，发送通知
- **数据分析**：统计对话模式、生成使用报告

**适用场景**：

- 企业级记忆系统
- 需要长期维护的项目

## 实践案例：universal-memory-mcp

### 当前架构

| 组件     | 实现方式                    | 平台        |
| -------- | --------------------------- | ----------- |
| **保存** | Plugin + MCP (session.idle) | OpenCode    |
| **搜索** | MCP (memory_search)         | 通用        |
| **引导** | Skills (memory-assistant)   | Claude Code |

**状态**：

- ✅ OpenCode：完全自动化（Plugin 监听空闲事件）
- ⚠️ Claude Code：半自动化（Skill 引导，需 AI 自觉调用）

### 未来规划

| 功能           | 实现方式                 |
| -------------- | ------------------------ |
| **完全自动化** | Plugin event hook        |
| **智能去重**   | MCP 内部实现             |
| **向量化搜索** | MCP + 外部 Embedding API |
| **自动整理**   | Plugin cron hook         |

## 选择建议

### 快速决策树

```
需要保存对话？
├─ 是
│  ├─ 需要 AI 主动调用？
│  │  ├─ 是 → Skills + MCP
│  │  └─ 否 → Plugin + MCP
│  └─ 想要事件驱动？
│     └─ 是 → Plugin + MCP
└─ 否
    └─ 不用 MCP
```

### 推荐方案

| 需求                        | 推荐方案                         | 理由                    |
| --------------------------- | -------------------------------- | ----------------------- |
| 简单搜索历史                | Skills + MCP                     | 快速、轻量              |
| 自动保存对话（OpenCode）    | Plugin + MCP                     | 事件驱动、可靠          |
| 自动保存对话（Claude Code） | Skills + MCP + Stop Hook         | 兼容现有能力            |
| 复杂自动化                  | Plugin + MCP + Skills            | 功能完整、可维护        |
| 多平台支持                  | Plugin + MCP                     | 统一 MCP，Plugin 做适配 |
| 完整记忆系统                | Plugin + MCP + Skills + 额外功能 | 最强但复杂              |

---

## 总结

Skills、MCP、Plugins 是 AI CLI 工具扩展生态的三个核心支柱：

1. **Skills** 定义 AI "应该做什么"
2. **MCP** 定义 AI "能做什么"
3. **Plugins** 定义 AI "何时做" 和 "如何做"

通过有机组合这三个组件，可以实现从简单的知识注入到复杂的自动化系统的各种功能。关键在于理解每个组件的职责边界，选择最适合当前需求的方案。

**最有效的组合**往往是：

- **Plugin + MCP**：自动化执行 + 类型安全
- **Skill + MCP**：行为引导 + 工具调用

而**最强大的方案**是三者的有机整合：Plugin 监听事件并调用 MCP，同时 Skill 引导 AI 使用 MCP 工具，形成完整的闭环。
