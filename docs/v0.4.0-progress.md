## 📝 Notes

### Design Decisions

1. **Why Gemini first?**
   - Free tier (1500 requests/day)
   - Lower dimensions (768 vs 1536/3072) = faster search
   - Good quality for general use

2. **Why conversation-based chunking?**
   - Preserves semantic boundaries
   - Better quality embeddings
   - Easier to trace back to source

3. **Why factory pattern?**
   - Easy to add new providers
   - Consistent API
   - Auto-detection of available keys

### Known Limitations

1. **No retry logic**: API calls will fail on network errors
2. **No rate limiting**: Could hit API limits on large batches
3. **No caching**: Same text will be re-embedded every time

### Future Improvements

- [ ] Add retry logic with exponential backoff
- [ ] Implement request queueing and rate limiting
- [ ] Add embedding cache to reduce API calls
- [ ] Support local models (Ollama, etc.)
- [ ] Add metrics/telemetry
